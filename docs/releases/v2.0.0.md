# FontInAss v2.0.0 — 服务端完全重写

v2.0.0 是一次不兼容的服务端 greenfield rewrite。旧服务实现已删除，不提供双栈或旧路由兼容层；Rust CLI 使用的 `/api/subset` 传输方式仍是 v2 正式协议，现有 CLI 调用方式无需修改。

## 主要变化

- 将服务端拆分为 contracts、字幕处理、字体目录、分享库、访问控制、活动记录、SQLite persistence 和 FS/R2 storage 八个 workspace 模块。
- 使用 Hono 路由链导出 `AppType`，Web 的 JSON 请求迁移到 Hono RPC；Zod validator 在服务端入口执行真实校验。
- ASS/SSA/SRT 解析、字体匹配、子集化、竖排 OpenType 表保留、UUencode 和 `[Fonts]` 回填收口到单一 `SubtitleProcessor.process()` 接口。
- 字体索引改用全新的 `data/fontinass-v2.db`，从 `FONT_DIR` 离线重建，不迁移旧索引 schema。
- 新增 R2 `_catalog/archive-manifest-v1.json`，保存无法由对象 key 还原的完整分享元数据。
- 分享库、字体管理、token 和活动记录统一使用新的正式端点；Web 手写 API 客户端由 948 行收敛到 231 行。
- Docker 改为 workspace frozen-lockfile 构建，先 build 后 recreate，并以 `version: 2` health contract 验证启动。

## 删除的旧接口

- `POST /api/sharing/import-index`
- `POST /api/fonts/repair-keys`
- `POST /api/sharing/upload-to-existing`，能力合并到 `POST /api/archives/upload`

正式端点由 43 个收敛为 40 个，详见 [v2 端点清单](../plans/2026-07-22-server-rewrite-endpoint-ledger.md)。

## 数据迁移边界

- 字体：从 `./fonts` 重建到 `data/fontinass-v2.db`。
- 分享库：从旧数据库一次性导出 published 元数据到 R2 manifest。
- 不迁移：upload token、处理日志、resolved 状态、rate-limit 计数和内存 cache。
- 旧 `data/fonts.db` 与旧镜像可以保留为回滚资产；R2 原 blob 不移动、不改名。

## 已完成验证

- workspace typecheck、测试、Web/Server/Docker 构建全部通过。
- 30,718 个字体文件、32,757 个 faces、107,253 个 names，SQLite integrity check 为 `ok`。
- 179 条已发布分享元数据写入并从 R2 manifest 恢复。
- Web 字体上传、ASS 子集化、分享审核、token 上传隔离冒烟通过。
- Rust CLI 真实 ASS 生成约 165 MB 输出，处理 79 个字体变体，无处理失败。
- 含 `!`、`'`、`(`、`)`、`*` 的 22 条 R2 URL 全部验证为 HTTP 200。
- 最终生产镜像 `sha256:d843c91c76c407074a5a934ef4c7e3b92617645be30387a3bb71a109fa08e35b` 部署 10 分钟后保持 healthy、0 restart，日志无 ERROR/panic/fatal。

## 升级

完整步骤见 README 的[从 v1 升级](../../README.md#从-v1-升级)。升级前备份 `data/fonts.db`；使用 R2 分享库时先运行 `bun run data:manifest`，再运行 `bun run data:reindex`，最后执行 `./rebuild-and-start.sh`。
